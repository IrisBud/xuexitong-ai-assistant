# 学校定制域名与 HTTP 页面

本说明对应 1.7.13 及后续版本的学校域名设置与 HTTP 兼容功能。先覆盖安装对应版本，只启用一份脚本，再分别配置学校来源和油猴用户匹配。

学校部署或代理的课程页可能使用自有域名。需要分别完成以下两项设置；只做一项不能解决注入、双面板或 iframe 接管问题。

## 1. 在脚本中批准学校来源

先停止自动运行。在已能运行脚本的官方页面，点击油猴图标 → 本脚本的 **学校域名设置**。

每行填写一个完整来源，只包含协议和主机，例如：

```text
http://mooc1.school.example
https://mooc1.school.example
http://work.school.example
```

上面是占位示例，请换成自己实际使用的学校来源。HTTP、HTTPS、不同子域名分别配置，最多 20 条；不接受通配符、路径、查询参数、账号或非默认端口。不要粘贴完整课程链接。删除配置行即撤销对应来源，保存后刷新所有相关页面，再手动开始。

设置保存在该脚本的管理器存储中，不会从页面消息、重定向或陌生 iframe 自动增加域名。来源通过后，仍会核对窗口关系、任务标识和 nonce；不会仅凭域名就授权提交或把任务点改为完成。

## 2. 在油猴中添加用户匹配

管理面板 → 点击该脚本 → 脚本自己的 **设置** → **包含/排除** → **用户匹配**，添加对应规则：

```text
http://mooc1.school.example/*
https://mooc1.school.example/*
http://work.school.example/*
```

保留“原始匹配”项，以继续支持官方地址。只加实际使用的课程主机；确认题目、文档或阅读 iframe 使用另一个来源时，再单独加入该来源，并在脚本的学校来源列表中批准。

全局设置中的“标签”只用于分类，填网址不会产生匹配效果。浏览器或油猴另有站点访问权限限制时，按正常授权流程设置。

脚本在未匹配的网站上不会执行，所以页面内设置不能自动修改 `@match` 或解决首次注入。脚本也没有默认扩大为全部 HTTP/HTTPS 网站。

用户匹配独立于源码中的原始匹配；后续覆盖更新应保留原脚本，并在该脚本设置中核对用户规则仍启用。删除脚本重装、导入另一份脚本或更换管理器后的迁移行为，请以实际管理器设置为准。[油猴官方说明](https://www.tampermonkey.net/faq.php?ext=fire&q=Q103)

## HTTP 支持范围

HTTP 页面缺少原生 `crypto.randomUUID()` 时，脚本用 `getRandomValues()` 生成标准 v4 UUID；缺少 `crypto.subtle` 时，使用内置 `@noble/hashes` 1.8.0 计算 SHA-256。字体字典、图片能力标识和讨论标识继续校验，不使用弱随机数，也不改写浏览器的 `crypto` 对象。[Web Crypto 接口规范](https://www.w3.org/TR/webcrypto/#crypto-interface)

HTTP 课程页依然没有传输保护。这项兼容不会修复 HTTP 的传输安全，不关闭证书检查，不伪装安全来源，也不自动跳转到猜测的域名或协议。远程 AI 接口继续要求 HTTPS；Key 保留在脚本管理器存储中，不通过课程页面或协作消息传递。

已适配路径中的章节、题目、文档、专题、讨论、作业和课程队列共用学校来源判断，仍各自检查页面路径及原有结构。页面外观相似不代表所有学校模板均已支持。缺少可靠完成回执时保持等待或待复核，不伪造任务点、成绩或下一节结果。

受控跨来源测验可以回报暂存结果；主页面不能独立读取具体测验标识时，只保留章节返回入口，不从子页随意报送的 ID 推断精确测验。返回后需人工选择和检查，不自动续填或提交。未接入脚本的跨来源组件仍保持等待。

## 可选：本地 Codex / WorkBuddy 桥接

本地桥接有独立的来源限制，不会从脚本设置中自动读取学校域名。确需在学校页面使用本地桥接时，可在启动桥接的同一个 PowerShell 会话中先设置：

```powershell
$env:XXT_SCHOOL_ORIGINS='http://mooc1.school.example,https://mooc1.school.example'
npm run start:codex
```

WorkBuddy / CodeBuddy 则使用 `npm run start:codebuddy`。替换为实际来源并重启服务；移除环境变量或撤销对应条目可取消批准。桥接仍只监听 `127.0.0.1`，保留 Host、本地连接码和鉴权检查。未配置的来源、`null`、其他端口及带路径的伪来源均拒绝。

## 初始化仍失败时

启动提示中的 **查看脱敏诊断** 只展示版本、协议、安全上下文、随机数/摘要 API 是否存在及简化错误码，不含主机、完整 URL、查询参数、账号、题目、Cookie、Key 或连接码。可以复制这段诊断反馈，不需要导出接口配置。

`E_RANDOM` 表示缺少安全随机数；`E_TEXT_ENCODER` 表示缺少文字编码能力；`E_HASH` 表示校验组件缺失；`E_ORIGIN` 表示当前来源未批准；`E_INIT` 表示其他初始化失败。检查浏览器版本、完整安装包与上述两项来源设置后再刷新。

本轮证据来自 Edge 的 HTTP/HTTPS 隔离页面、模拟课程结构、模拟脚本管理器存储与模型回执；不能代替学校实页、真实任务点、实际成绩或真实账号权限验收。请先核对面板和页面状态，再决定是否使用自动操作。
