# Issue #7：视频任务点确认

此修复自 1.7.10 起收录，并累计保留 1.7.9 的课程入口与章节接续修复。后续版本继续包含这些改动；实际安装版本以脚本面板为准。

用户截图中的 `<i></i>` 是空的装饰节点。状态来自它外层的 `.ans-job-icon.ans-job-video`，截图明确显示 `aria-label="任务点未完成"`，所属任务容器为 `.ans-attach-ct.videoContainer`。

本次改动：

- 视频任务明确标为“任务点”或“任务点未完成”时，优先服从该状态，不让外层残留的 `ans-job-finished` 类覆盖它。明确的“任务点已完成”支持 aria 标签和图标内正文。
- 根据视频图标、容器和模块识别视频任务，兼容尚未插入播放器、通用播放器网址和跨来源组件。只使用当前容器自己的图标和 iframe，不能借用嵌套或相邻任务的完成状态。
- 每次判断必需媒体是否完成时重新读取对应任务点；播放结束事件和播放器子页发来的结束消息本身都不等于平台确认。等待任务点变化后，仍遵守原 90%/100% 播放策略。
- 已识别的音视频任务仍在加载时显示对应等待提示。普通异常仍沿用每章最多一次恢复、记录待复核与跳过规则；跳过不会被记作平台完成。手动停止、预览和夜间休息保护保留。
- 已知音频页可能在正常结算后保留旧 aria 标签，继续沿用该页已经验证的完成类回执，不将视频的冲突优先级扩大为音频规则变更。

验证使用用户截图中可见节点的脱敏重建和隔离浏览器。旧 1.7.7 在人工构造的“完成类与未完成标签冲突”状态下复现跳过视频，通用加载网址的视频标记被误分为未知任务；这些结果证明相应代码路径存在缺陷，不能证明报告者真实课程一定出现过同样的残留类。没有取得报告者完整课程运行日志，也没有安装候选到真实课程验证任务点或成绩。

具体通过数量和最终安装字节以本地交付报告及回归记录为准，不把既有正式版或不同字节的测试结果套到本候选。
