WorkBuddy / CodeBuddy 连接

使用官方 CodeBuddy CLI，登录与 WorkBuddy 相同的站点和账号。积分能否使用，要查自己的用量明细。

按正式版 1.8.3 整理6 分钟阅读

这篇讲什么
准备完整源码和 Node.js安装官方 CLI登录本人账号启动 18764 本地服务保存到学习助手自己核对积分和模型权限

准备完整源码和 Node.js

此连接从正式版 1.7.7 提供。只安装油猴脚本还不够：先下载并解压完整源码 ZIP，进入含 package.json 的文件夹，再打开终端。

需要 Node.js 20.11 或更高版本。Windows、macOS、Linux 都按各自终端运行；下面命令在项目目录执行。

node --version
npm --version

安装官方 CLI

npm install --prefix ./src/local/codebuddy --cache ./src/local/npm-cache --no-audit --no-fund @tencent-ai/codebuddy-code@2.177.1

这条命令把 CLI 和缓存放在项目私有目录。首次安装的依赖较大，失败时保留终端错误，不要从别人处导入登录文件或账号凭据。

已经安装官方 CLI 的用户，也可以沿用自己的安装。程序找不到时，再按完整连接说明设置实际入口。

登录本人账号

npm run login:codebuddy

按官方菜单选择与 WorkBuddy 相同站点、相同账号，在官方页面完成登录。国内站、国际站、企业账号要分别核对，不能只因为账号名称相同就假定可以跨站使用积分。

首次创建的登录配置在 src/local/codebuddy-config，不要分享。自定义配置目录时，登录与服务启动要使用同一个目录，否则可能出现“已经登录但仍要求认证”。

启动 18764 本地服务

npm run start:codebuddy

保持服务窗口开启。默认地址为 http://127.0.0.1:18764，模型交由 CLI 选择。若需指定模型，使用自己账号已确认可用的完整 ID，具体环境变量见完整连接说明。

不要把 WorkBuddy 积分数量、模型显示名称或其他平台的 ID 当成本平台模型 ID。面板不会覆盖本服务启动时选定的模型。

Codex 服务使用 18763；两种服务的端口和连接码不同，不要混填。

保存到学习助手

  1. 面板“接口 → 添加 / 编辑接口”，选择本地 CodeBuddy / WorkBuddy。
  2. Base URL 填 http://127.0.0.1:18764。
  3. 打开 src/local/codebuddy-token.txt，将完整连接码填入“API Key / 本地连接码”。
  4. 先选择文字用途，保存并点“测试 AI”。需要图片，再配置图片用途并单独测试。

不要填 WorkBuddy 密码、Cookie、其他 API Key，或 Codex 的连接码。服务能连接后，还要通过实际模型测试；文字和图片分别报告结果。

自己核对积分和模型权限

测试和答题可能消耗账号积分。先在官方“套餐与用量”记下时间，只做一次文字测试，再看对应的模型调用明细，核对账号、站点、模型、扣减类型和时间。

模型限免、入账延迟和奖励使用范围都会影响账面变化。不能只看积分总数下降，就认定某类奖励积分已经可用于此连接。

已有一个国内站账号完成过合成文字、数字图片测试，并核对到 CLI 基础积分消耗；奖励积分未完成实际扣减验收。这些结果不代表其他账号权限，也不证明真实课程填写、提交或得分。
